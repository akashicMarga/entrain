Entrain — Pipeline & the Director Agent

A music system where the listener is inside the loop: sense how the room responds, steer what plays in real time. The intelligence lives in perception, the fast policy, and a slow Director agent that plans the set. The generator is a frozen renderer steered by a single style vector.

No LLM/VLM ever runs in the fast loops — latency, numeric inputs, and stochastic output make them the wrong tool there. The agent steers character, the policy steers position.

3 · The Director agent — why "agent"

It's called an agent because it isn't a single function — it juggles several jobs at once, over time, with memory and a goal. It's the slow planner sitting above the fast controller.

What it handles

  • Authors the anchors. Writes/revises the prompts that define the current musical range (Directive). This is where character — including drums — actually lives (drums come from the prompts, not the controller).
  • Holds the arc. Restraint and narrative: a naïve reactive loop always-ramps-up or oscillates. The agent plans build → peak → breakdown over minutes.
  • Judges its own moves. Reads EpisodeBuffer.transitions(lag_s) — "did synchrony rise after I last pushed?" — and adapts. Credit assignment, not reflex.
  • Fuses modalities. Numeric trends + an optional VLM scene read + the operator's natural-language instruction → one decision in language.
  • Triggers snapshots. Captures before/after frames on each change for cheap VLM comparison — no streaming video needed.

Interface & implementations

Protocol Director — initial() → Directive, revise(ctx) → Directive | None. Model-agnostic; the fast path is untouched.

4 · Memory — the EpisodeBuffer

A single frame is a state; knowing whether a move worked needs the trajectory plus a log of what we did, paired with a lag. That's bookkeeping over numbers we already compute — not a video model.

Two streams in

add_state(t, StateVector)per frame · the room over time
add_action(t, weights / Directive)what we did
snapshot(t, frame, state)on Directive change

Two seams out

  • director_context(now) → window means + energy trend → the agent's slow view.
  • transitions(lag_s) → for each action, the room's response after the lag (skips actions too fresh to have landed).

The Transition tuple

(state_before, action, state_after, lag_s)

  • response_synchrony — the headline reward proxy (engagement), not arousal.
  • response_energy · response_valence — supporting deltas.

Same object, two uses: the director's "what changed when I tuned the music" read and the offline (s, a, response) dataset that trains the learned policy / finetunes the agent. Building memory = building the training set.

6 · What reaches the generator (MRT2)

Style

Blended anchor vector → musical character. cfg_musiccoca. Authored by the agent, positioned by the policy.

Drums

−1 mask / 0 none / 1 hit. Movement-driven pulse + accents, gated on calibrated movement. drum_gate onset_rise_sigma

Notes

Hand height → pentatonic lead pitch. cfg_notes

Tempo travels on its own channel, never inside the style vector (style = character, not BPM). The responsive:false flag freezes steering → the static-generative A/B baseline.

7 · What's frozen vs. learned, by stage

StageWhat changesThe learnable boxes 🪸
1 — prove the loopzero training. HeuristicPolicy + StaticDirector + per-session calibration.none (heuristics)
2 — survive real conditionssupervised affect read-out; rPPG; validate synchrony.perception/affect.py
3 — the contributionlearned fast policy (imitation/offline-RL on EpisodeBuffer tuples); the agent authors prompts.policy/learned.py · the Director agent

The generator is never trained — that's solved and GPU-months away. The original problem is the policy + agent that close the loop, and the reward (synchrony) they optimize. Memory (EpisodeBuffer) is what makes that learnable without live experimentation.
